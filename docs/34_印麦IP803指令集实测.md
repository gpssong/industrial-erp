## 现场四个已知坑（发给操作的人，先念这四句）

1. **扫到 0 台但机器开着** ⇒ 十有八九是 Android 8.1–11 的系统**定位总开关**关着（权限已授也不报错，静默回空列表）。下拉快捷开关打开「使用定位」再扫；Android 12+ 不需要定位。
2. **机器在列表里找不到** ⇒ 未配对过的 IP-803 可能**无名广播**，调试页会把它滤掉。先在系统蓝牙设置里配对一次，让它带上名字。
3. **报「连接失败」但状态又说已连上** ⇒ 已加连接代次过滤，正常不该出现；出现了就记下**第几次点连接、前后各等了多久**（这是 §9 的一条副证，别重连成功就当没事）。**连一次等结果，别连点。**
4. **发到一半报「BLE 写队列忙」** ⇒ 先记 `missingAcks` 与 `elapsedMs` 再重试；重试把片间隔调大（30 → 60 → 100）。片间隔本身就是 B4 要定的默认值 —— 这一格不是麻烦，是数据。
5. **⚠ 中文打不进「原始字节」框（2026-11-05 实测踩到）** ⇒ 页面对每字符做 `charCodeAt(i) & 0xff` 再 `btoa`，
   所以「测试」只发出 **2 字节**（`4B D5`，日志「准备发送 2 字符 → base64 4 字符」就是它）。
   **这不是打印机坏了，也不是 Q1 的证据** —— 机器收到的是无意义字节，没反应是正常的。
   发中文按上面「样本原文 ③」的**粘贴串**走；ASCII 样本 ①②④⑤ 不受影响，照常打字或整段粘贴。
   （根因是 B1 Step 3 的编码选择器还没实装 —— 那是唯一能直接打中文的路子。）

## 另一条出口：PC Chrome 探测页（路径 A）

只用于**快速验 ASCII 样本 ①②④⑤ 与拿服务/特征 UUID**；中文与编码（③）以及最终结论一律以 APK 为准
（JS 的 `TextEncoder` 编不出 GBK）。⚠ Chrome 只让 `getPrimaryServices()` 看见 `optionalServices` 白名单里的服务 ⇒
「连上了但列出 0 个可写特征」是探测页自己挡的，**不得据此判 Q1**。

## 结论对渲染器的影响（B2 的实现口径，逐条对应上面证据）

| 口径 | 取值 | 出处 |
|---|---|---|
| 指令集 | TSPL（`TsplLabelRenderer` 按 Task B2 原样实现，**不需要** `CpclLabelRenderer`） | Q1 |
| 中文字体号 | 常量 `TSS24.BF2`，24×24 点阵 | Q2 |
| `CHARSET` | 渲染器与插件默认都用 **GBK** | Q3 |
| 头部四行 | `SIZE 80 mm,60 mm` / `GAP 2 mm,0 mm` / `DIRECTION <0 或 1>` / `CLS`，结尾 `PRINT 1,1`，行尾 **CRLF** | ① 出空白张 = 四行全被解析 |
| `DIRECTION` | **B2 二选一并写进单测**：改 `DIRECTION 0` 让坐标与肉眼一致（推荐），或保持 `1` 并在模板坐标里按反向算 | 硬约束 1（三次复现） |
| 纸面点数 | **203dpi ⇒ 80mm=640 点、60mm=480 点**（不是 800） | 硬约束 2 反证 |
| 超宽处理 | **渲染器自己按 640 点量宽度并拆行/缩字号**；机器侧静默丢尾、不折行、不报错 | 硬约束 2 |
| `QRCODE` 形参序 | `QRCODE x,y,L,4,0,A,"<内容>"`（写法 A，Ruling 非实测） | ④ |
| `BARCODE` | `BARCODE x,y,"128",h,...` 照 TSPL 标准序写；**纸面/扫码证据欠在 B4** | ⑤ |
| BLE 分片 | 片 **180** 字节、片间 **30ms**、超时余量按 **60ms/片**；只走 `WRITE_TYPE_DEFAULT`（props=8，无 write-no-response）；JS 侧插件名 **`LabelBle`** | GATT 事实 + 轮 10–13 |

## 已经确定的两条硬约束（不等 Q2/Q3，B2 现在就得按这个写）

这两条是 ①② 两张纸顺带测出来的，**不是计划里的样本，但比样本更有用**：

1. **`DIRECTION 1` 会把内容转 180°** —— ② 那张纸上的英文字是倒着的（我们的头部固定发 `DIRECTION 1`）。
   ⇒ B2 要么把头部改成 `DIRECTION 0`，要么保持 1 并在模板坐标里按反向算 —— **只能选一个，且必须写进单测**，
   否则以后所有「标签印反了」的报障都要重新取证一次。
2. **一行文字超出纸宽 ⇒ 固件静默丢掉尾部，不折行、不报错** —— ② 的 `abcdefg` 直接没了。
   起点 x=40、字体"2"、放大 2×2 的 43 个 ASCII 字符放不完 80mm。
   - **纸宽点数已被这条反证出来**：用户读数「印到 `IP803 PROBE ASCII 0123456` 就断了」= **25 个字符**。
     丢的是整字符不是笔画 ⇒ 断点是一个确定的宽度上限。25 个字符这个数与「203dpi ⇒ 80mm = 640 点」
     自洽（`40 + 25×24 = 640`，即字体"2"在 2×2 放大下每字符 24 点）；若真是 800 点则还能再容 6 个字符，
     与实际不符 ⇒ **按 203dpi、80mm = 640 点（60mm = 480 点）算**，**不是** 800 点。
   - ⇒ `TsplLabelRenderer` **必须自己按 203dpi（80mm = 640 点）量宽度并拆行/缩字号**，
     绝不能把「发出去没报错」当成「印全了」。合格证那种长公司名首当其冲。
     ⚠ 中文按字体 `TSS24.BF2` = 24 点/字 ⇒ 一行最多 `(640−x)/24` 个汉字，11 字公司名要 x≤376，
     而这条规则目前只是算术，**还没在中文行上实测过**（B2 的单测必须钉住 640 这个常量）。
   - ⚠ 这条只能靠渲染器兜，机器侧没有任何反馈通道（`print()` 回的 `missingAcks=0` 只说明蓝牙发完了）。
