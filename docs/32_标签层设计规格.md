## 0. 一句话与三条前提变更

**做一层与打印机厂商无关的「标签主数据 + 模板 + 渲染 + 打印中心」，本周先跑通三类标签，主输出通道改为车间手机蓝牙直发 TSPL。**

用户在方案落地过程中给出了三条**推翻原文档前提**的事实，本规格按新事实写：

| # | 新事实 | 对设计的影响 |
|---|---|---|
| N1 | 手上是**印麦 IP-803** 蓝牙标签机，主打 **80×60** 标签纸，**车间手机蓝牙连接打印** | 主通道 = 手机端蓝牙直发指令，**不是**云打印服务商；后端在 Docker 里摸不到蓝牙，所以**渲染在服务端、出纸在手机端** |
| N2 | **合规要素暂时不上标签**，但工业生产许可证**证书编号要放上去**（已提供证书 PDF） | 六项合规要素**全部存进主数据**（以后要上不用改库），但默认模板只引用**生产者名称 + 浙 XK16-204-01155** |
| N3 | 车间**Wi-Fi 和 4G 都有** | 服务端渲染接口从车间可达，**不需要离线兜底**（不必在手机本地存整套模板重实现渲染）；但打印机绑定仍是**手机本地**的（见 §7） |

## 2. 数据模型

### 2.1 标签主数据：一条 `sys_config` JSON

决策依据：本 ERP 已有 `sys_config` + `SysConfigController` 白名单机制（`SYS_NAME` / `SYS_FACTORY` / `XK_AUDIT_RETENTION_YEARS` …），六项里五项是**全局单值**，为它们建表是过度设计；第六项"检验员代号"天然属于人，落 `sys_user`。

- `config_key = LABEL_MASTER`，`config_value` 存 JSON：

```json
{
  "producerName": "舟山市鹏程包装有限公司",
  "producerAddress": "浙江省舟山市舟山高新技术产业园区大成九路32号",
  "xkNo": "浙 XK16-204-01155",
  "execStandard": "Q/ZPC 1-2017",
  "storageCondition": "储存在清洁、干燥、通风、温度适宜的库房内，避免阳光照射，距热源不小于 1.0 m，堆放合理；贮存期为自生产之日起一年"
}
```

（`producerName`/`producerAddress`/`xkNo` 逐字取自用户提供的《全国工业产品生产许可证》与准予行政许可决定书；`storageCondition` **逐字取自** [docs/27 §6.4](27_企业标准QZPC1-2017检验条款对照.md) 贮存条款原文 —— **不要自行改写这两段文字**，它们是对外标识，须与证书和企标一致。**发证日期 2023-03-10、有效期至 2028-07-14** 记在该配置的备注列，便于以后做到期提醒。）

- **六项全部存，模板默认只引用前两项**（生产者名称、XK 证号）—— 这是 N2 的落地方式：以后要上合规要素只改模板，不改库、不改后端。
- `SysConfigController` 的 key 白名单加 `LABEL_MASTER`。**读写分两头，各自复用既有机制，不为标签新造配置端点**：
  - **写** = 既有的通用 `PUT /system/config/value {key, value}`（权限沿用系统配置编辑）。代价如实说：**改厂名/XK 证号只有有系统配置权限的人能做** —— 这本来就是对的，对外标识不该人人可改。
  - **读** = 新增 `GET /base/label/master`，挂 `base:label:list`。因为 App 的打印中心和 PC 打印中心都要读它做渲染，不能让只有业务权限的人去调 `/system/config/*`。

- `sys_user.inspector_code VARCHAR(32) NULL` —— 检验员代号，用户拍板"加列"。渲染时从**当前登录用户**取；为空时该字段渲染为空串并在预览里标出（不是报错，避免卡住打印）。

## 3. 模板元素模型（`elements` JSON）

6 种元素类型，坐标/尺寸单位**全部是点（dot）**，渲染器按 `dpi` 换算：

```json
{
  "type": "text",           // text | multiline | barcode | qrcode | line | rect
  "x": 20, "y": 40,
  "text": "批号",           // 字面量（type=text/multiline/rect 用作标题）
  "field": "batchNo",       // 或从上下文取值的字段名（见 §3.2）
  "size": 24,               // 字号：点高，text 用 24/32/48 三档；barcode/qrcode 用 module 宽/尺寸
  "bold": false,
  "align": "LEFT",          // LEFT | CENTER | RIGHT（text 相对 x 起点的对齐）
  "w": 300, "h": 24,        // rect / line 才有意义；line 只取 w 或 h 之一
  "required": true          // 该字段缺失时预览标红（见 §5）
}
```

### 3.1 六种类型

| type | 语义 | TSPL | 飞鹅 |
|---|---|---|---|
| `text` | 单行 | `TEXT x,y,"font",rot,"内容"` | 明文行 |
| `multiline` | 多行（地址、品名折行） | 按行拆多条 `TEXT` | 明文多行 |
| `barcode` | 一维条码（默认 CODE128，批号/单号） | `BARCODE x,y,"128",h,rotation,narrow,wide,"内容"` | `<BR>` + 条码指令 |
| `qrcode` | 二维码（单号+批号） | `QRCODE x,y,E,7,A,0,"内容"` | `<QR>内容</QR>` |
| `line` | 横线/竖线（分区） | `BAR x,y,w,h` | — |
| `rect` | 矩形框（外框/区块标题底） | `BAR x,y,w,h`（h=1 或 w=1） | — |

### 3.2 字段名（`field`）取值口径

渲染器只认**上下文里存在的字段名**；未知字段名 = 模板错误，保存模板时校验并报错（照 v1.1.162 飞鹅模板保存语法闸的先例做，别把错误留到打印那一刻）。

**FG_ROLL 成品卷标**（数据源：`prd_finished_in` + `prd_order` + `base_product` + `mes_batch`）
`productName` `productCode` `spec` `unitName` `qty` `batchNo` `productionDate`（取 `mes_batch.production_date`，**不是** `bill_date`）`orderNo` `billNo` `gramWeight` `width` `thickness` `colorNo` `producerName` `xkNo` `inspectorCode`

**RAW_PALLET 原料垛标**（数据源：**按采购入库明细行**出，`pur_receipt` + `pur_receipt_detail` + `base_product`）
`productName` `productCode` `supplierName` `batchNo` `qty` `unitName` `receiptBillNo` `receiptDate` `inspectionReportNo`（v1.1.158 的 `BG-YL-…`）`producerName`
⚠️ 品名/批号/数量在**明细行**上，表头只有供应商/单号/报告号 —— 加载器必须按行展开，一次打印可能出 N 张。

**CARTON 箱标**（数据源：**按销售出库明细行**出，`sal_delivery` + `sal_delivery_detail` + `base_product`）
`customerName` `deliveryAddress` `deliveryPhone` `productName` `spec` `qty` `unitName` `orderNo` `deliveryBillNo` `deliveryDate` `batchNo`
（客户名 + 地址/电话来自表头，用户拍板"印客户名 + 地址/电话"）
`batchNo` 口径已核对（**不是待查项**）：审核选批次出库（v1.1.152）后，[SalDeliveryService.java:453](../backend/src/main/java/com/industrial/erp/modules/sales/service/SalDeliveryService.java#L453) 把 `joinBatchNoForDisplay()` 的结果写进 `sal_delivery_detail.batch_no VARCHAR(64)` —— **多个批次用 `|` 连接**，并且**行尾若有一个裸 `|`，表示该行还包含"无批号"的那部分数量**（[:736-747](../backend/src/main/java/com/industrial/erp/modules/sales/service/SalDeliveryService.java#L736)）。
⇒ 箱标的 `batchNo` 元素**原样打印这串**（批号本来就是给追溯读的，不做二次加工）；但**默认模板要把它放低位小字号**，因为一行可能挤三四个批号，`|` 串在 80mm 宽上会溢出到框外。溢出检测（元素宽度 vs `width_mm×dpi`）列进渲染器校验。

> 三类标签的字段来源都已在设计阶段读实体/DDL 核对（`prd_finished_in` **没有** `prod_date`，故生产日期取 `mes_batch.production_date`；`pur_receipt` 表头**没有**品名/批号/数量，故原料垛标必须按明细行展开）。若实施时发现某字段实际列名不同，**改本节并注明**，不要在代码里静默兜底。

## 4. 渲染管道与两个渲染器

```
LabelContextLoader(bizType, bizId[, detailLineId])   →  Map<String,Object> ctx   // 每个 bizType 一个实现
LabelTemplateRenderer(template, ctx)                 →  List<ResolvedElement>    // 取值/格式化/必填校验，厂商无关
TsplLabelRenderer  (geometry + List<ResolvedElement>) →  TSPL 指令文本 + 字节编码  // 主通道
FeieLabelRenderer  (…)                               →  飞鹅指令文本              // 次通道
```

**关键约束：**

1. `ResolvedElement` 是**唯一的中间接口**。以后加第三家（CPCL / 爱印云 / ZPL）只写第三个渲染器，主数据、模板、元素模型、日志、页面**都不动** —— 这一条是本次"唯一不浪费的投入"的技术保证。
2. 坐标换算只发生在 `TsplLabelRenderer`/`FeieLabelRenderer` 内部，元素里存的都是点。
3. **服务端渲染，手机端出纸**。后端在 Docker 内无法访问蓝牙；手机拿渲染结果直发打印机。
4. `barcode`/`qrcode` 的**打印走打印机指令**（TSPL `BARCODE`/`QRCODE`、飞鹅 `<QR>`），服务端**不生成图片**。zxing 只为 §6 的屏显预览服务（见 §6.3）。

## 5. 缺失值与错误处理

| 情况 | 行为 |
|---|---|
| `required=true` 字段在 ctx 里为空 | **不阻断打印**；预览里该元素标红并列出字段名，日志 `status` 仍可为成功。理由：车间不能因为一个代号空就停下不出标签 |
| 模板引用了上下文中不存在的 `field` 名 | **保存模板时**报错（语法闸），打印时不会再遇到 |
| 元素超出画布（`x`/`y`/宽度换算后越过 `640×480` 点） | **保存模板时**报错并指出越界的元素序号与越界量 |
| 渲染异常（元素 JSON 坏了） | 打印接口 500 + 明确 `msg`，**并在 `base_label_print_log` 落失败记录** |
| 蓝牙发送失败 | App 弹错误 + 调 `/print/log` 记 `status=FAIL, error_msg`，把 TSPL 文本回显给用户以便复制导出 |
| 无权限（403） | 走项目统一拦截；PC 侧逐请求 try/catch，一个失败不清空其他已取到的数据（v1.1.145 教训） |

## 6. PC 端

### 6.1 两个新页

- `pc-web/src/views/base/LabelCenter.vue` —— 标签打印中心：选 `biz_type` → 选单据（成品入库单 / 采购入库单 / 销售出库单，明细行可选）→ 选模板 → **预览** → 导出 TSPL 文本 / 走飞鹅打印 / 打印日志。
- `pc-web/src/views/base/LabelTemplate.vue` —— 模板管理：元素表格编辑（不画布拖拽，见下）+ 尺寸/dpi/间隙/份数 + 保存期语法闸 + 存为默认。

**元素编辑用表格不用画布**：80×60 上 6 种元素、每张模板十来个元素，表格（类型/x/y/字段/字号/必填）比 A4 那套 myprint-design 画布便宜一个数量级，而且元素模型本来就是点坐标。画布拖拽列入后续。

### 6.2 「品牌与工厂」tab 接真（这是修 bug，属于本期范围）

现状：[System.vue](../pc-web/src/views/system/System.vue) 的 `brandForm` 里**统一社会信用代码 / XK 许可证编号 / 工厂地址 / 工厂编码 / 单据页脚 / 英文名称**六个输入框能填能保存提示成功，但 `saveBrand()` 只把 `systemName` 和 `factory` 落到 `SYS_NAME` / `SYS_FACTORY`，**其余六个字段直接丢弃**，重进页面也回显不出来（假成功）。

本期改：`saveBrand()` 真保存、进页面真回显，落库分两类，**都用通用 `PUT /system/config/value`，不新建端点**：

| tab 上的字段 | 落到 |
|---|---|
| XK 许可证编号 / 工厂地址（= 生产地址） | `LABEL_MASTER.xkNo` / `LABEL_MASTER.producerAddress` |
| 系统显示名称 / 工厂名称 | 既有 `SYS_NAME` / `SYS_FACTORY`（现状已正确，不动） |
| 统一社会信用代码 / 工厂编码 / 英文名称 / 单据页脚 | **各自一个新 `sys_config` key**（`SYS_CREDIT_CODE` / `SYS_FACTORY_CODE` / `SYS_EN_NAME` / `SYS_FOOTER`），一并加进 `SysConfigController` 白名单 |
| 执行标准编号 / 贮存条件 | `LABEL_MASTER.execStandard` / `LABEL_MASTER.storageCondition`（tab 上暂无输入框 ⇒ 本期只由 SQL 种子写入，以后要界面化再加，不算缺口） |

即：**tab 上六个假成功的字段全部接真，没有一个继续骗人**。`LABEL_MASTER` 只装与标签渲染相关的键，其余四个是通用系统信息，各自独立键更贴合既有 `sys_config` 的用法。
Logo 上传仍只在本机预览，**不在本期接服务端**（避免把"接真"扩成"图片存储"）。

### 6.3 预览怎么出图

后端 `POST /base/label/preview` 返回**元素级结构化结果**（解析后的文本/条码内容 + 点坐标），前端用绝对定位 HTML 在 80×60 等比画布上渲染；条码/二维码用 **zxing 服务端出 SVG/PNG** 一并返回。

- ⚠️ 预览忠实于**版式**，不忠实于**打印机中文字体**——中文实际效果由 §9 取证决定。这一点必须在页面上写出来，否则用户会拿预览当打印机输出判断。

### 6.4 新增依赖

`backend/pom.xml` 加 `com.google.zxing:core` + `com.google.zxing:javase`（**当前无 zxing**，现在所谓二维码全靠飞鹅云 `<QR>`）。只服务预览。

## 7. App 端（蓝牙主通道）

### 7.1 Capacitor 原生插件 `LabelBlePlugin`（Android only）

本工程 App = uni-app 编译 H5 → Capacitor 套壳。**因此 Web Bluetooth 在 Capacitor WebView 里不可用，厂商 UniApp SDK/插件市场包装不进来**，必须手写 Capacitor Android 插件 —— 与 `NativePrintPlugin` / `NativeScannerPlugin` / `NativeSharePlugin` 同一先例、同一注册方式（`build-app.sh` 的 `[4.5/5]` 会重新追加 `:capacitor-share`/`:capacitor-app` 手工 include，**APK 只能走 `scripts/build-app.sh`**）。

桥面（JS ↔ Native）：

| 方法 | 语义 |
|---|---|
| `scan()` | 扫描并回调设备列表（BLE + 经典 SPP 都要，IP-803 用哪种由 §9 取证定） |
| `connect(mac)` / `disconnect()` | |
| `print(contentBase64, {mtu, chunkDelayMs})` | 服务端 TSPL 文本 → base64 → 原生**分片写**（BLE 特征写必须按 MTU 切片 + write-with-response 逐片确认，否则长指令静默丢包 = 标签打一半） |
| `status()` | 连接态，用于页面显示 |

失败一律回 JS 层异常 + 由页面落打印日志（§5）。

### 7.2 页面

`app/src/pages/base/label-print.vue`（工作台入口）：选类型 → 选单据/明细行 → 拉预览 → 选已绑定打印机 → 打印。
沿用 App 既有约定：`ref/reactive/onMounted` 从 `'vue'`、`onLoad` 从 `'@dcloudio/uni-app'`；取路由参数走 `takePendingRoute || activeRouteQuery || query` 三级优先级；`async onLoad` 里初始化**必须 `await`**（v1.1.142 深链竞态教训）；按钮是 `<uni-button>`、`disabled` 看 `outerHTML`。

### 7.3 打印机绑定放手机本地

**决策：不入库。** 绑定（设备名 + MAC）存手机本地存储，每台手机各绑各的。

理由：① 车间会有多台手机 + 多台机器，一对多映射在库里建模是猜需求；② 换班/换机时手机自己重绑比 PC 改配置快；③ MAC 落库对服务端渲染毫无用处。
代价（如实说）：换手机要重绑一次；后台看不到"哪台手机绑了哪台机器"，只能从打印日志的 `printer_mac` 事后推。

## 8. 权限

三个权限点（`base:label:*` 前缀跟 `base:product:*` / `base:warehouse:*` 一致）：

| perm | 覆盖 |
|---|---|
| `base:label:list` | 查单据/明细行、`GET /base/label/master`、读上下文（只读） |
| `base:label:template` | 模板增删改查（`LABEL_MASTER` 的写**不挂在这里**，走通用系统配置端点，见 §2.1） |
| `base:label:print` | 渲染 + 导出 + 打印 + 写打印日志 |

**必须遵守本项目两条铁律：**

1. **铁律 4「两套 perms 口径」**：`sys_menu` 里启用 F 型行（`status=1`）**和** `sys_role_menu` 授权行**必须同批做**，只做一半必然出"隐形按钮"或"接口 403"。载体 parent 挂**工作台（id=1）**，挂 `parent_id=0` 会挤到 root 找不到。→ **sql/156**。
2. **App 端白名单**：[pc-web/src/views/system/Role.vue](../pc-web/src/views/system/Role.vue) 的 `APP_MENU_WHITELIST` 里没有的 perm **界面上根本授不出去**。本期要把 `base:label:list` + `base:label:print` 加进白名单。**按本项目惯例，加 App 白名单需要 PC 与 APK 协同发布才能配合 App 侧判断 —— 本期 APK 无论如何要重出（新蓝牙插件），所以这个成本为零。**

授权口径：`base:label:print` 按"**镜像于该单据本身的查看权限**"发放 —— 已能看成品入库/采购入库/销售出库的角色才补标签打印行，本次不为标签新建业务角色。⚠️ **只镜像、不创造新权限面**（同 sql/154 的拍板口径）。

后端注解一律带 `mode = SaMode.OR` 并 OR 上对应单据的 `:list` perm，避免"能看单不能打"的第三次 403。

## 9. 第 0 步：真机指令集取证（**硬闸**）

**印麦官方公开机型页只列 IP-801 / IP-802 / IP80-BT，没有 IP-803** ⇒ 手上这台机器的指令集是**未验证**的。同时"能不能打 80×60"从来不是风险，**中文怎么出**才是：

取证要回答三个问题，答案直接决定渲染器怎么写：

| # | 问题 | 分支后果 |
|---|---|---|
| Q1 | 这台机器吃不吃 TSPL（`SIZE`/`GAP`/`TEXT`/`QRCODE`/`PRINT`）？ | 不吃 → 改 CPCL（`*! 0 N` 那套），`TsplLabelRenderer` 变 `CpclLabelRenderer`，**元素模型不动** |
| Q2 | 中文靠**内置字库**（`TEXT` 直接出中文）还是必须**位图**（`BITMAP`）？ | 必须位图 → 服务端要加 Java2D 单色点阵渲染（BufferedImage → 每行字节打包），本期工作量翻倍，需重新拍板 |
| Q3 | 字节编码是 **GBK / GB18030 / UTF-8**？ | 编码错 = 中文全是乱码方块，且**不报错**（最难发现的一类） |

**做法**：手工发 **5 条最小指令样本**（① `SIZE`+`GAP`+空 `PRINT` 验指令被吃 ② 纯 ASCII `TEXT` ③ 中文 `TEXT` ④ `QRCODE` ⑤ `BARCODE` CODE128 + 人眼/手机扫码验读），逐条打出来肉眼看。发送路径两条，任选先通的一条：
- **A：PC 上真 Chrome 浏览器 + Web Bluetooth**（最快，不用碰本工程代码；注意这与 §7.1 "Capacitor WebView 里 Web Bluetooth 不可用" **不矛盾** —— 那边说的是套壳 App 的 WebView，这里是桌面 Chrome）。
- **B：先只写 `LabelBlePlugin` 的 `scan/connect/print` 三个方法 + 一个调试页**，从 APK 直发。取证更贴近真实链路，但要多出一次 APK。

取证结果写进 `docs/34_印麦IP803指令集实测.md`（含每条指令、机器响应、纸面照片描述）。

**闸门规则**：**Q1/Q2/Q3 没有答案之前，不写 `TsplLabelRenderer` 的实现** —— 因为**"蓝牙打印"和"导出 TSPL 文本"用的是同一个渲染器，两个都被这道闸挡住**（本期交付里这两项是"闸后"）。
- **闸前可做**（与指令集无关，取证期间并行推进）：两张新表 + `inspector_code` 列、`LABEL_MASTER` 主数据与「品牌与工厂」tab 接真、元素模型与 `LabelContextLoader`（三种 bizType）、`LabelTemplateRenderer`（含未知字段名与越界校验）、PC 模板管理 + 打印中心 + 结构化预览、飞鹅次通道 `FeieLabelRenderer`、打印日志、权限与 sql/156、App 的 `LabelBlePlugin` 骨架（只为取证服务）。
- **闸后才写**：`TsplLabelRenderer` 的指令拼装与编码、App 蓝牙打印联调、TSPL 文本导出。
- 取证不通过就换路：Q1 否 → 同接口写 `CpclLabelRenderer`；Q2 要位图 → 服务端加 Java2D 单色点阵（**这一条会让后端工作量明显上升，需要重新拍板，不能默默做**）。无论走哪条，主数据、模板表、元素模型、日志、页面**都不动**。

## 11. 已如实记录的后果（用户已确认接受）

1. **PC 打不了蓝牙**，标签出纸只在手机；PC 只做设计、预览、导出、飞鹅、日志。

3. 打印机绑定在手机本地，**换手机要重绑**，后台看不到绑定关系。
4. `CERT` 只留枚举，**合格证本期打不出来**——14 项标志、3 签、留样那一套按 N2 暂不上标签。
