# 25 · ESP32 吹膜米克重采集接入指南 (v1.1.119)

> **目标**: 吹膜机米克重 (g/m²) 只显示在车间触摸屏, 办公室/远程看不到 → 无法质量追溯与工艺分析。
> 用 **ESP32 旁听 RS485(Modbus) 总线** 读出米克重, **WiFi 回传 ERP**, MES 侧实时曲线 + 超标判定 + 历史追溯。
>
> **已落地** (v1.1.119 开发周期, 随 jar v1.1.125 部署到双站): 接收侧全链路 (后端 3 表 + 免登录态上报端点 + PC 实时曲线页 + SQL seed)。
> **待落地** (现场, 本文档第 4 章): ESP32 固件 + Modbus 寄存器反推 —— 全链唯一未知数。

---

## 1. 数据流全景

```
吹膜机控制器 (冠尚达, RS485 从站, Modbus RTU 9600/8N1)
   │  寄存器表: 米克重 g/m2 · 线速 m/min · 累计产量 ...
   ▼
[485↔USB 模块 MAX485/SP3485] ── 接 ESP32 的 UART (DI↔TX, DE/RE 短接↔GPIO)
   │
ESP32 (Modbus RTU 主站, WiFi 连车间网络)
   每 5s: 读寄存器 → ×scale 换算 → 手搓 JSON (camelCase)
   │  HTTP POST /api/device/weight/report   (带 X-Device-Key 头)
   ▼
ERP 后端 (设备密钥自校验, 免 Sa-Token 登录态)
   写 mes_weight_sample + 刷新 mes_weight_device.online_status
   ▼
PC Weight.vue (/production/weight): 实时曲线 (5s 轮询) / 采样明细 / 超标率统计 / 通道配置
```

**两条路径严格分离** (设计核心, 见 ADR-0008):
- **设备上报** `POST /device/weight/report` — 免登录态, 走 `X-Device-Key` 密钥 (ESP32 无人值守刷不了 30 天 Sa-Token)。
- **PC 查询** `GET /mes/weight/**` — 带登录态, 走 Sa-Token + `mes:weight:*` perm。

## 2. 数据模型 (3 张表, sql/129)

| 表 | 用途 | 关键字段 |
|---|---|---|
| `mes_weight_device` | 采集器注册 (ESP32↔ERP 对应) | `device_code` 唯一, `online_status`, `last_report_time`, `baud_rate`/`slave_addr`/`protocol` (协议反推回填), `device_key_masked` (只存后 6 位掩码) |
| `mes_weight_channel` | 通道配置 (寄存器表 + 设定值 + 公差) | `reg_start`/`reg_type`/`scale` (反推回填), `set_weight` (工艺目标), `upper_tol`/`lower_tol` |
| `mes_weight_sample` | 采样流水 (时序, 曲线源) | `actual_weight`, `line_speed`, `deviation`/`deviation_pct`/`is_over` (后端算), `prd_order_id` (可关联工单) |

⚠️ **雪花 ID** (全局 `mybatis-plus id-type: ASSIGN_ID`): 手写 INSERT 时 **不要 AUTO_INCREMENT**, 且 ID 别贴近 INT64_MAX (如 `9990000000000000001` 会 `ERROR 1264 Out of range`), 用 `1000000000000001` 这类低位量级。

⚠️ **部署顺序**: 先灌 `sql/128` (BOM 单位回填, 幂等但含状态位 UPDATE, 按 R24 连跑 3 次), 再灌 `sql/129` (本脚本)。两脚本编号曾撞车 (都叫 128), 已把称重脚本改名 129, 别再用旧名。

## 3. 接收侧 (已实现, 双站在线)

### 3.1 鉴权模型 (ADR-0008)

- **设备密钥走 env `ERP_DEVICE_KEY`**, Controller `@Value` 注入, **不硬编码不落库** (表里只存后 6 位掩码 `device_key_masked`)。
- **fail-closed**: `ERP_DEVICE_KEY` 留空 = 拒绝一切上报 (`500 服务端未配置设备密钥`); key 不匹配 = `401`。
- **白名单只写精确路径**: `SaTokenConfig` 登录态豁免口加 **`/device/weight/report`** (不是 `/device/**`) —— 这个 notMatch 是全项目唯一登录态豁免口, 写通配等于把设备端所有端点裸奔到公网。
- **双站用不同 key** (canary-first): 飞牛 canary 一个 key 验证无问题, 再同步 home 用另一个 key。两 key 各自写各自 `.env`, **不进 git / 不进镜像** (密钥只走 gitignored 的 `.env`)。
- **ESP32 不发 Origin 头 → 不需要配 CORS** (CORS 是浏览器概念)。

### 3.2 端点

| 路径 | 方法 | 鉴权 | 用途 |
|---|---|---|---|
| `/device/weight/report` | POST | `X-Device-Key` | ESP32 上报采样 (免登录态) |
| `/mes/weight/device/page` | GET | `mes:weight:list` | 采集器列表 |
| `/mes/weight/channel/list` · `/channel` (POST) | GET/POST | `list`/`edit` | 通道配置 (寄存器表+设定值+公差) |
| `/mes/weight/curve` | GET | `mes:weight:list` | 曲线数据 (**按时间正序**, 后端倒序取 limit 再翻转, 防曲线停在开机那刻) |
| `/mes/weight/stats` | GET | `mes:weight:list` | 每通道均值/极值/超标率 |
| `/mes/weight/sample/page` | GET | `mes:weight:list` | 采样明细分页 |

上报报文 (一次可带多通道):
```json
{
  "deviceCode": "GSDB01",
  "fwVersion": "0.1",
  "samples": [
    {"channelNo":1, "actualWeight":29.6, "lineSpeed":120, "collectTime":"2026-10-25 12:00:00"}
  ]
}
```
**字段名 camelCase, 与 `MesWeightSample` 实体一致** —— ESP32 手搓 JSON 最易错的就是大小写, 写错 = Jackson 静默 null → 落库空值 (R22/R23 那类"不报错的静默错")。

**审计字段陷阱**: 设备写入无登录态, `MybatisPlusConfig.metaObjectHandler` 的 `SecurityContext.getUserId()` 返回 null → 审计 `create_by` 恒 NULL。`MesWeightService.reportSamples()` **不改全局 handler** (会波及全库 60+ 表), 而是显式 `setCreateBy(DEVICE_OPERATOR_ID=999L)` (需先在 `sys_user` 建 999 号"设备采集"虚拟账号), 靠 `strictInsertFill` 只填 null 字段语义原样落库。

- **采样明细** Tab: 分页表格, 实测/偏差/超差 tag

## 3.3 全字段上云 + 三端入口 (v1.1.119b / v1.1.126)

> 背景: 冠尚达高精度米重控制系统 MCGS 屏上实际有 **12 个量** (设定克重/实际克重/计米长度/设定长度/料斗流量/计米重量/上牵引Hz/当前长度/机器产量/当前重量/下牵引Hz/计米速度/克重修正), 但 v1.1.119 的 `mes_weight_sample` 只存了 6 列 —— 其余量上不到云。

**`sql/130_v1119b_mes_weight_full_fields.sql`** — 幂等 ADD COLUMN × 6 (`set_length`/`current_weight`/`upper_hz`/`lower_hz`/`machine_yield`/`gauge_fix`, 全可空, `information_schema` 探测 + PREPARE/EXECUTE, 可连跑不炸)。实体 + `MesWeightSampleMapper.xml` 的 `selectCurve` 同步扩 SELECT 别名。设备上报带这些字段 → `reportSamples` 直写 → 全字段落库。

**三端入口**:
| 端 | 页面 | 说明 |
|---|---|---|
| PC | `views/production/Weight.vue` | 实时曲线 (5s) + 采样明细 (含 6 新列) + 统计 + 通道配置; 驾驶舱生产 Tab 也有迷你实时卡 |
| PC 入口 | `views/erp/Hub.vue` 「生产管理」分类卡第 5 方块 | `/erp?cat=production` 快进入口「吹膜米重采集」icon `Odometer` → `/production/weight` |
| App/H5 | `app/src/pages/production/weight.vue` | 采集器 chip + 8-KPI + 纯 view 迷你趋势 (不引 echarts) + 采样分页 + 通道统计; 工作台「全部功能 → 生产管理」出图标「⚖ 吹膜米重采集」 |

**App 端信封坑 (R23)**: App 拦截器已 `resolve(d.data)`, 页面读 `r` 不可再读 `r.data` → 统一 `(r && (r.records || r.data)) || []` 双形态防御 (PC 端信封未拆封, 仍读 `r.data.records`, 两边相反)。

**版本**: v1.1.126 四源同步 (R15) — `pc-web/package.json` + `app/package.json` + `app/src/manifest.json` (1.1.126 / versionCode 1126) + `application.yml` + `SystemVersionInitializer`。

## 4. ESP32 固件 + Modbus 寄存器反推 (现场待做, 全链唯一未知数)

> 冠尚达 (GUANSHANGDA) 吹膜机米克重控制器**无公开寄存器文档** (公开渠道查无) —— 协议反推只能现场做。

### 4.1 硬件接线

| 项 | 值 |
|---|---|
| ESP32 | ESP32-WROOM-32 (30-pin, UART0 引出), WiFi 模块 |
| 485 模块 | MAX485 / SP3485 (2 个若多控制器; 带终端电阻拨档) |
| 接法 | 模块 `DI`↔ESP32 TX(GPIO), `DE/RE` 短接↔另一个 GPIO (方向控制), 模块 `A/B`↔控制器 `485-A/485-B` (**A 接 A, B 接 B, 不能反**) |
| 串参 | 9600 / 8N1 (Modbus RTU 标准); 控制器若 19200/115200 以手册为准, 回填 `mes_weight_device.baud_rate` |
| 电源 | **控制器 24V 供电, 别直接接 ESP32** (烧 3.3V 逻辑); 485 模块单独 5V 供, GND 共地或隔离 (防地环流烧 485) |

`de/RE 合并`驱动方向: 读时「先 DE=1 发请求 → 发完立刻 DE=0 收响应」, 固件两个 GPIO 时序切分。

### 4.2 寄存器反推 (半天能出结果)

1. **先拿控制器型号铭牌** (机壳正面/侧面, 通常中文厂家 + 型号)。型号出 → 寄存器表基本锁死。
2. 确认 **485 口** (左侧 D-sub 白口 or 板载 3 针蓝头) + **从站地址** (常 01, 有些默认 0 或拨码设)。
3. **扫输入寄存器** (功能码 04, 拿 USB-485 转接器 + `pymodbus`, 先用电脑扫别用 ESP32):
   ```python
   from pymodbus.client import ModbusSerialClient
   c = ModbusSerialClient('COM3', baudrate=9600, parity='N', stopbits=1); c.connect()
   for addr in range(0, 256):
       rr = c.read_input_registers(addr, 1)
       if not rr.isError() and rr.registers[0] != 0:
           print(hex(addr), rr.registers[0])
   ```
4. **对着屏幕找值**: 扫出一批"值在动的寄存器"后**手动让膜厚波动**, 看屏幕米克重数字变 + 同时打印这些寄存器, **哪个跟着变且数值×缩放≈屏幕值就是米克重寄存器**; 线速同理。
5. 回填三样到 `mes_weight_channel`: `reg_start` (寄存器地址) + `reg_type` (4=输入/3=保持) + `scale` (缩放系数, 原始 int÷scale=g/m²)。
6. **最省事**: 直接问厂里电工"米克重寄存器地址多少" —— 他们常知道。

### 4.3 固件骨架 (Arduino, `ModbusMaster` + `HTTPClient`)

```cpp
#define MODBUS_ADDR 0x01            // 从站地址 (现场确认)
uint16_t vals[8];
void loop() {
  if (millis() - lastPoll >= 5000) {          // 5s 一拍, 别更快 (采样表会爆)
    lastPoll = millis();
    modbus.poll();
    for (int i=0;i<REG_CNT;i++) modbus.readInputRegisters(REG_START+i, 1, &vals[i]);
    reportSample(vals);
  }
}
void reportSample(uint16_t *v) {
  // 字段名 camelCase, 与 MesWeightSample 实体一致
  String body = String("{\"deviceCode\":\"GSDB01\",\"fwVersion\":\"0.1\",\"samples\":[")
    + "{\"channelNo\":1,\"actualWeight\":" + String(v[0]*SCALE,3)
    + ",\"lineSpeed\":" + String(v[1]*SCALE,2)
    + ",\"collectTime\":\"" + rtcIso() + "\"}]}";
  HTTPClient http;
  http.begin("http://<ERP_HOST>/api/device/weight/report");
  http.addHeader("Content-Type","application/json");
  http.addHeader("X-Device-Key", DEVICE_KEY);   // 编译常量或 NVS, 别进 git
  int code = http.POST(body);
  if (code != 200) { /* 重试队列 / LED 闪 */ }
}
```

**固件要落的 4 个坑** (对应接收侧约束):
- `X-Device-Key` 必填且正确 (后端空=拒收, 错=401)
- JSON 字段名 camelCase (写错 = 静默 null)
- `deviceCode` 必须先注册 (`mes_weight_device.device_code`, 后端查不到就拒收防孤儿数据)
- 5s 一拍别更快 (每台每 5s 一行 = 17 万行/天/通道, 采样表是时序流水)

`collect_time` 是**设备侧时钟**: 用 NTP 校一次 RTC, 无网时用启动时刻外推。
