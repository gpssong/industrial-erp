# 31 标签打印方案（ERP 打实体标签）

> 状态：**方案，未实施**。等用户答复文末 4 个问题后才排期。
> 起因（用户原话，2026-11-03）：「https://apps.apple.com/cn/app/标签管家/id1663162151 我希望 erp 能打印标签，能把这个标签管家的功能集成进去吗？给我一个方案。」

---

## 一、结论先说

1. **「标签管家」这个 iOS App 本身不能被集成** —— 它是厦门爱印科技（启锐标签 QiRui 硬件配套）的桌面/手机标签编辑软件，没有开放 App 级 API、URL Scheme 或剪贴板协议，外部程序无法把数据推给它、也无法命令它打印。
2. **但它背后的厂商能力是可以集成的**，有两条正规接口：
   - **PSDK**（<https://iprtapp.com/psdk/>）：客户端直连打印。支持 Dart/Flutter、Android、iOS、**Web / 小程序 / UniApp**、HarmonyOS、Windows/macOS；脱离 App 独立运行；蓝牙经典 / BLE / WiFi / USB；指令集 CPCL、ESC、ESC-POS、**TSPL**；标签排版在**设备端**渲染。
   - **爱印云打印**（<https://iprtapp.com/cloud-print/>）：服务端 API（HTTP / MQTT / WebSocket），API Key + Secret 鉴权，支持 Helm/K8s 私有化部署。
3. **ERP 里已经有一条完整的云打印链路**（飞鹅云），加第二家服务商是"照抄一遍"的工作量，不是新建一套 —— 见第三节。
4. **真正卡住"能打合规标签"的不是打印通道，是主数据**：XK 合格证要求的 14 项标志里，**生产者厂名、厂址、XK 证号、执行标准编号、贮存条件、检验员代号**在库里没有任何结构化字段（只有 OQC 检验记录的文本里出现过）。通道打通了也印不出合规标签。
5. **明确否决**"用标签管家手工导 Excel 打印"：那样批号、数量、生产日期全靠人工誊抄，批次追溯与防错（poka-yoke）在标签这一环直接断掉，且没有打印审计，XK 检查时无法自证标签内容与检验记录一致。

## 二、ERP 现在的打印现状（盘点，均为已上线代码）

| 能力 | 实现 | 载体/纸张 | 说明 |
|---|---|---|---|
| 云打印（票据） | [FeiePrintClient](../backend/src/main/java/com/industrial/erp/modules/production/client/FeiePrintClient.java) `POST http://api.feieyun.cn/Api/Open/`，`action=Open_printMsg`，签名 `sha1(user + ukey + stime)` | 飞鹅 58mm 小票 | FreeMarker 模板渲染后按 `<CB>` `<B>` `<BR>` `<C>` `<QR>` `<CUT>` 标记出纸 |
| 模板管理 | 表 `sys_feie_print_template`（**DB 行优先于 classpath**），classpath 在 `backend/src/main/resources/templates/print/*_feie.ftl`（9 个） | — | v1.1.162 已加保存期语法校验闸 |
| **现在所谓的「打印标签」** | 飞鹅 `prd_finished_in_feie.ftl`（成品入库单据类型） | **58mm 热敏小票** | 内容 = 品名/规格/数量/批号 + 单号二维码。**不是不干胶标签，热敏纸也不适合食品外包装长期标识（会褪色）** |
| A4 单据设计器 | myprint-design 前端画布 | A4 | 浏览器 `window.print()` / chromePrinter，走 PC |
| App 原生打印 | Capacitor `NativePrintPlugin`（Android `PrintManager`） | ISO_A4 | iOS 端没有实现 |
| 服务端 PDF | OpenPDF + flying-saucer | A4 PDF | 用于导出/归档 |

**缺口清单（本次要补的）**：

- 没有 **TSPL / ZPL / CPCL** 任何一种标签指令的实现；
- 没有第二种打印机品牌/通道的抽象（只有飞鹅一家）；
- 打印机没有「类型」字段（小票机 / 标签机 / A4），标签纸没有尺寸字段（40×30 / 60×40 / 100×60…）；
- 后端**没有 zxing 依赖**，二维码靠飞鹅云的 `<QR>` 指令在云端出图；自建标签通道需要自己生成条码/二维码（`<QR>`、TSPL `QRCODE` 也可靠打印机指令，但预览要本地渲染就得自己画）；
- 生产者厂名/厂址/XK 证号/执行标准/贮存条件/检验员代号 **无结构化字段**（见第一节第 4 条）。

## 三、三条可行路线

### 路线 A：ERP 内自建「标签」层（不绑定任何硬件）

**做法**：① 补主数据（厂名/厂址/XK 证号/执行标准/贮存条件/检验员代号）→ ② 把「标签」从「小票」里拆出来，做独立的标签模板 + 纸张尺寸 + 条码/二维码元素 → ③ 打印出口先复用飞鹅（能出二维码、能切纸），硬件到位后再接第二家。

- **优点**：零硬件采购即可开工；主数据补完，XK 检查的合格证条款才算真正落到系统里；后面 B/C 都复用这一层。
- **缺点**：飞鹅 58mm 热敏小票**不能代替不干胶标签**，A 阶段只是内容和数据打通，物理标签仍要等硬件。
- **工作量**：后端 1 张标签模板表 + 1 个渲染/取数服务 + 主数据字段（含迁移 SQL）；PC 一个模板管理页；App 复用现有打印按钮。约 2 个版本批次。

### 路线 B：接「爱印云打印」HTTP API（推荐作为标签机接入首选）

**做法**：把现有 `FeiePrintClient` 抽象成打印服务商接口（`provider = feie | aiyin`），第二家实现走爱印云打印 OpenAPI（HTTP/MQTT，API Key + Secret）。凭证沿用 v1.1.165 已建好的「系统设置 → 对接方式」卡片模式：`sys_config.AI_INTEGRATION` 同级加一块、脱敏回显、保存即生效不重启。

- **优点**：与现有云打印链路同构，**架构上最省**；不依赖现场某台电脑开机；**阿里云接管期间照常可用**（这是 A/C 都要小心的点，见路线 C）。
- **缺点**：标签机要能连外网/或自建云打印服务；要买爱印的服务或私有化部署；排版能力受其模板体系约束。
- **前置**：需要先有爱印云打印的账号与 API Key（用户侧动作）。

### 路线 C：App 端 PSDK 直连蓝牙/WiFi 标签机

**做法**：App（uni-app + Capacitor）集成启锐 PSDK 的 UniApp/Android 插件，手机端蓝牙直连标签机，标签在**手机端**渲染，直接下 TSPL/CPCL。

- **优点**：**最贴合现场** —— 仓库/车间工人用手里的手机 + 一台蓝牙标签机就能出标签，不需要任何服务器能访问打印机；不需要外网。
- **缺点**：① 后端在 NAS 的 Docker 容器里，**物理上够不到 USB/蓝牙打印机**，所以只能做客户端直连；② 只覆盖 App，PC 端不能打；③ iOS 端 Capacitor 插件要另写；④ 每次换 APK 要重出包（本项目 APK 只能走 `scripts/build-app.sh`）。
- **⚠️ 同类限制提醒**：v1.1.165 已经踩过一次"代码正确但拓扑不成立"—— OCR 从**本机 `ERP_UPLOAD_PATH` 磁盘**读图，阿里云接管期间跨机读不到就静默返回空。凡是"依赖和后端同机的硬件/文件"的方案都要先问一句：**接管那天还成立吗？** TSPL over TCP 9100（局域网直连打印机）就是这类：主站在家里能打通，阿里云那台够不到你家的打印机。

### 对比

| | A 自建标签层 | B 爱印云打印 | C App PSDK 直连 |
|---|---|---|---|
| 需要新硬件 | 否 | 是（爱印标签机 + 联网） | 是（蓝牙标签机） |
| 阿里云接管期间可用 | ✅ | ✅（走公网 API） | ⚠️ 与后端无关，可用；但 App 域名要能访问 |
| 覆盖端 | PC + App | PC + App | 仅 App（iOS 需另做） |
| 离线/无外网 | — | ❌ | ✅ |
| 改造面 | 中（主数据 + 模板 + 表） | 中（服务商抽象 + 凭证） | 中（原生插件 + APK） |
| 建议顺序 | **① 先做** | ② 若买云打印能力 | ② 若买蓝牙标签机 |

## 四、推荐落地方式

**第一步（不含硬件采购，任何时候都能开工）**：走路线 A 的 ①② —— 补主数据 + 把标签模板从票据里拆出来。这一步的产出（标签字段、版式、条码内容规则）是 B/C 的共同前提，不会白做。

**第二步按硬件定**：
- 买**带云打印的爱印/启锐机型**且现场能联网 → 路线 B；
- 买**蓝牙标签机**、要在车间/仓库用手机随手打 → 路线 C；
- 两者不冲突，B/C 都能作为 A 之上的第二个 provider。

## 五、需要用户答复的 4 个问题（未答复前不排期）

1. **现有标签打印机**：有没有？品牌型号（是否启锐/爱印）、接口（USB / 蓝牙 / 网口 / 云打印）？
2. **打哪几类标签**：成品卷膜/袋的合格证标、原料包装标、还是库存批次货位标？纸张尺寸与内容版式（有无现成样品标签照片可给）。
3. **在哪里打**：仓库/车间用手机打，还是在办公室 PC 打？（这直接决定 B 还是 C）
4. **合格证 14 项是否要全落进标签**：特别是**生产者名称、地址、生产许可 XK 编号、执行标准编号（Q/ZPC 1-2017）、贮存条件、检验员代号** —— 这 6 项目前库里没有字段，要答"是"就得先建主数据。
