## 0. 一句话与六条裁定

**给标签模板加所见即所得的编辑能力：PC 画布设计、App 现场微调；排版数学仍然只有服务端一处，所以屏幕上看到的就是纸上打出来的。**

用户在澄清阶段给的六条裁定，本文全部照此写：

| # | 裁定 | 对设计的约束 |
|---|---|---|
| D1 | 所见即所得**必须等于真机** | 排除前端自算字宽、排除 `myprint-design`（它产 FreeMarker/HTML，不产 TSPL）；也排除"后端光栅化成位图"（位图能忠实，但拖不动、选不中、无法逐元素标问题）。⇒ 实现路线取 **A：后端回拆行后的点阵盒子，前端只管画和拖** |
| D2 | App 端**只做现场微调** | 手机改位置/倍率/份数，不改模板集合、不改纸头、不做字段映射 |
| D3 | 画布数据源**示例值为主 + 可选真单** | 需要一种"不挑单据也能算出内容宽度"的上下文模式（§3.4） |
| D4 | 元素模型**扩少量：独立横纵倍率 + 旋转** | 11 键一个不动，只加 4 键；类型体系不扩（不做圆弧/图片/表格线） |
| D5 | 存储**覆盖模板 + 留可回滚快照** | 一张历史表 + 一个 rollback 端点 + 界面「回上一步」（§7） |
| D6 | 权限**设计=超管，微调=主管** | `base:label:template` 要**扩 App 端授权**——这条**有意推翻** v1.1.167 同日批次"只补导航入口、不扩授权面"的窄范围决定。那次是范围最小化的选择，不是长期原则；本文 §6.3 是新的拍板 |

## 3. 架构与数据流

### 3.1 核心决策：排版数学不许有第二处

`lineSegments` / `wrapBudgetDots` 目前只服务渲染器。本设计把它们上面提到一个**唯一的布局出口**：

```java
// 新增 com.industrial.erp.modules.base.label.LabelLayout
public static List<Box> segmentsFor(ResolvedElement e, int paperW)   // Box = {x, y, w, h, content}
```

- `TsplLabelRenderer.textBlock()` 改为**消费** `LabelLayout.segmentsFor()` 的盒子来发 `TEXT`（含加粗那条 x+1）；
- 新端点 `resolve` 直接把这些盒子回给前端；
- 保存闸 `validate()` 判越界用的还是同一批盒子。
- 载体要跟着扩：`ResolvedElement`（v1.1.167 定的"唯一中间接口"）得把 §4 那四个**声明值**带过来（现在只有 `fontSize`/`w`/`h`）。否则布局函数拿不到 `mulX/mulY/cell/rotate`，只能在渲染器里再读一次 `LabelElement`——那就是第二处数学。`ResolvedElement` 加字段对四个既有消费方（渲染器、闸、预览、日志）是向后兼容的。

重构的前提是**行为不变**：单测 T1 钉住"重构前后发出的 `TEXT` 行逐字节相同"。这条如果不成立，本设计的其余部分就没有意义——画布画的和打印机打的两套数，正是 v1.1.167 已经付过学费的坑（`LabelGeometry` 类注释里的 B3b）。

### 3.2 新端点契约

```
POST /base/label/resolve
{
  "bizType": "FG_ROLL",
  "elements": "[{\"type\":\"text\",...}]",   // ← 未保存的草稿，原文 JSON 串
  "header": { "widthMm":80, "heightMm":60, "gapMm":3, "dpi":203, "direction":"NORMAL", "copies":1 },
  "sample": true,                            // false 时带 bizId / lineIds，按真实单据算
  "bizId": null, "lineIds": null
}
→ {
  "widthDots": 640, "heightDots": 480,
  "issues": [ { "index": 2, "field": "prodDate",
                "message": "该标签类型不存在字段: prodDate" },
              { "index": 5, "field": null,
                "message": "y=440 起高 60 点，越过下边界 480 点，越界 20 点" } ],
  "labels": [ { "elements": [ {
      "type":"text", "x":24, "y":40, "content":"背心袋 30×45cm",
      "mulX":2, "mulY":2, "rotate":0, "svg":null,
      "segments": [ {"x":24,"y":40,"w":288,"h":40,"content":"背心袋 30×45c"},
                    {"x":24,"y":80,"w":12, "h":40,"content":"m"} ],
      "overflow": false, "missing": false, "field": "productName"
  } ] } ]
}
```

三个要点：

1. **收草稿，不收已存模板 id。** 画布上正在拖的东西还没落库。因此 `resolve` 内部**先跑一遍保存闸**（现 `LabelTemplateRenderer.validate(elementsJson, bizTypeCode, …)`，[:55](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelTemplateRenderer.java#L55)），把问题按元素序号标在盒子上。这是 F6 的正面解法——顺带把表格式编辑器"保存失败才知道配错"的体验问题一并解决。
   两种着色**都不从 `issues` 来**：`issues` 是 `validate()` 的返回原样，`ValidationIssue(int index, String field, String message)` 三元组（[ValidationIssue.java:9](../backend/src/main/java/com/industrial/erp/modules/base/label/ValidationIssue.java#L9)），**没有 level 字段**；橙/红是元素级那两个既有布尔 `overflow` / `missing`（[ResolvedElement.java:20-22](../backend/src/main/java/com/industrial/erp/modules/base/label/ResolvedElement.java#L20)）。别把两者混成一个数组：`validate()` 根本不判取值，"必填但这一单的字段是空的"永远只出现在 `missing` 里。
   橙和红的**后果也不同**，这点不能含糊：橙（几何越界、字段不存在）保存时会被拦；红（必填取值为空）**只提示、不拦**——它来自 render 侧，沿用 docs/32 §5「车间不能因为一个代号空就停下不出标签」。画布提前标出来是为了让人看见，不是为了新增一道闸。
   ⚠ 这条改变了保存闸的角色：从"只在提交时拦"变成"**边画边提示 + 提交时仍然拦**"。拦的那一半**不许因为画布上已经提示过就放松**，服务端仍是最终裁判（§5.5）。
2. **`header` 里的纸头数字复用现成校验**。`BaseLabelTemplateService.applyDefaults` 已经有"A8 裁定 R3：纸头必须为正数，先于闸"的那段逻辑（[BaseLabelTemplateService.java:128-145](../backend/src/main/java/com/industrial/erp/modules/base/service/BaseLabelTemplateService.java#L128)）。`resolve` 不能自带一套更宽的纸头判断，否则草稿能过、保存不能过。
3. **用户可提交的数据一律夹上限**（F5 同一处置）：坐标、`mulX/mulY`、`cell`、`w/h` 全部在进数学之前夹到区间，`resolve` 不许因为一个大坐标就 OOM 或者拼出几百 MB 的段数组（§4 规矩三）。

### 3.3 往返策略

- **拖动过程纯本地平移盒子**（跟手，不发请求）；
- 松手，或属性面板改动 **150ms 防抖**后，回一次 `resolve`；
- App 微调页更粗：**只在松手时**回一次（手机网络 + 4G 车间，多打几个来回只会更卡）。

### 3.4 示例上下文挂在 loader 上

`LabelContextLoader` 加一个默认方法，三个实现各给一组典型值：

```java
default List<Map<String,Object>> sample() { ... }
// 成品卷标：品名"背心袋 30×45cm"、客户"领先未来"、数量 1200、批号"PH20261106A"…
```

`LabelContextService` 加 `loadSample(bizTypeCode)`，走的是**同一张 loader 路由表**、并且和 `load()` **共用同一个主数据并集**（`producerName`/`producerAddress`/`xkNo`/`execStandard`/`storageCondition`/`inspectorCode` 那六个键，[:40-45](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelContextService.java#L40)）。`load()` 本身一行不动。

> 与对话里呈现 §1 时的一句话有偏差，这里按实施事实写清：呈现时说的是"`LabelContextService` 零改动"，准确说法是"**`load()` 不动，加一个 `loadSample()`，并把并主数据那段抽成私有方法供两者共用**"。如果 `sample` 不并主数据，画布上生产者那两行就永远显示成空，示例等于没示例。
> "新增一类标签只加一个 `@Component`" 那条架构规矩没有被破坏——示例值就长在同一个 loader 上。

### 3.5 与既有 `/preview` 的关系

`/preview` 一个字节不改。它服务打印中心（有真单、要出张数、要塞 PNG），`/resolve` 服务编辑期（草稿、示例、要盒子与问题清单）。两个端点**共享** `LabelTemplateRenderer.render` + `LabelLayout`，不共享请求 DTO（`LabelPreviewRequest` 加字段会让两个场景的必填性打架）。

## 4. 元素模型扩四键

现有 11 个键（type/x/y/text/field/size/bold/align/w/h/required）一个不动，**只加 4 个，全部"不声明就走今天的老路"**：

| 新键 | 含义 | 不声明（缺省/0）时的行为 |
|---|---|---|
| `mulX` | 横向字库倍率，整数 1–8 | 按今天：`fontFor(content, size)` 用 size 推 |
| `mulY` | 纵向字库倍率，整数 1–8 | 同上 |
| `cell` | 二维码模块边长（点/模块），2–8 | 按今天：`qrCell(size)`（[LabelGeometry.java:73](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelGeometry.java#L73)） |
| `rotate` | 0 / 90 / 180 / 270 | 0（与今天 `TEXT` 第 4 参写死的值一致） |

因为缺省即旧行为，**sql/155 那三条种子模板与线上已存模板字节不变、渲染结果不变**，零数据迁移。

三条规矩：

1. **`size` 不删、不降格**，但在有 `mulX/mulY` 之后它只是"没声明倍率时才用到的原料"。属性面板上**只显示「宽倍 × 高倍」和派生的「字高 ≈ 基点点阵 × mulY ÷ 8 mm」**（那个 ÷8 就是 203dpi 的 8 点/毫米；300dpi 机器要按 §12 那条重新推），不再让车间的人猜"字号 24 是什么意思"——这个坑 `LabelElement.java:13-14` 的注释自己都在道歉：二维码那栏填的是"名义字号"，实际要的是模块边长。`cell` 就是让二维码能直接填边长。
2. **取有效倍率只有一个函数**：`LabelGeometry.effectiveMul(LabelElement e, String content)`，**返回值复用现成的 `Font` 记录**（`Font(String name, int baseW, int baseH, int mulX, int mulY)`，[LabelGeometry.java:79](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelGeometry.java#L79)，`perCharDots()/lineHeightDots()` 两个派生量已经在它身上）。它内部就是今天 `fontFor(content, size)`（[:96](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelGeometry.java#L96)）那条算法，只是"元素声明了 `mulX/mulY` 就用声明值、否则回落到 size 推导"。**`fontFor` 的公开调用点现在只有两处**——渲染器 [:104](../backend/src/main/java/com/industrial/erp/modules/base/label/TsplLabelRenderer.java#L104) 与保存闸 [:194](../backend/src/main/java/com/industrial/erp/modules/base/label/LabelTemplateRenderer.java#L194)——两处都换成 `effectiveMul`，`fontFor` 随之降级为它的私有回落分支（公开的同源出口留两个，早晚有人调错那个）。这是 §3.1 那条"数学不许有第二处"在模型层的延续；否则会出现"画布按 mul 画、打印按 size 打"。
3. **上限一律夹，不报错**：`mul` 夹 1–8，`cell` 夹 2–8，`rotate` 非四倍直角归 0。理由同 F5——elements 现在是用户可提交的自由数据，画布手柄理论上能拖出一个 999。

**诚实标注的风险**：8 倍中文 = 192 点 ≈ 24 mm，这个量级真机只验到 1 倍（24 点）和种子模板用到的档位。⇒ §9 的 P3 去现场取证旋转时，**顺带把 `mulX/mulY` 1..8 与 `cell` 2..8 逐档各打一张纸**，同一次跑腿，别把"看着能配、打出来未知"的档位留在产品里。

**`rotate` 里唯一不确定的是 `BARCODE`**（F2）：P3 的取证脚本要先回答"旋转角到底在第几位"。**答不出来就条码不实现旋转**（`TEXT`/`QRCODE` 照上），不为一条没证据的形参猜。

`rotate` 键**不在 P1 出现**（§9）：一个"能存进库、渲染器不发、闸不判"的键就是死数据，还会让 P2 的 App 界面误以为能选。

## 5. PC 画布编辑器

### 5.1 文件动作：改 1 个、新增 2 个

不是拆成 4 个——现有表格 markup 留在原文件里，避免为了好看做一轮无价值搬迁。

| 文件 | 动作 | 职责 |
|---|---|---|
| `pc-web/src/views/base/LabelTemplate.vue` | 改造成容器 | 持有 `rows`（**唯一真源**）、模板头、撤销栈、防抖 `resolve`、保存。两个 tab 共用**同一个 `rows` 引用** |
| `pc-web/src/components/LabelCanvas.vue` | 新增（哑组件） | 只吃 `resolve` 回来的盒子 + 选中态；只 emit `选中/移动/缩放/删除`；不碰接口、不含业务规则 |
| `pc-web/src/components/LabelInspector.vue` | 新增 | 右侧属性面板：字段/字面文本、宽倍×高倍（二维码是 `cell`、条码是 `h`）、对齐、加粗、必填、旋转（P3 才亮起） |

**不动的东西**（有意，别顺手改）：路由、`meta.perm`（`base:label:list` / `base:label:template`，[router/index.js:29-30](../pc-web/src/router/index.js#L29)）、保存走的 `PUT /base/label/template`。改这三样会重新引入"幽灵权限"那类只有非超管才暴露的洞。

### 5.2 视图与坐标

默认 **1 mm = 6 px**（80×60 → 480×360），缩放范围 4–12。
这条是必要项，不是加功能：真机 1 点 = 0.125 mm，而 `LabelCenter.vue` 那个预览画布 `VIEW_W=320` 的尺度下 1 点只有半个像素——**拖 1 点你根本看不见它在动**。

### 5.3 交互口径（每条都可验证）

| 操作 | 规则 | 为什么这样定 |
|---|---|---|
| 拖动 | 位移换算成点后**四舍五入到整数点** | TSPL 坐标只认整数；非整数落进 elements 就是脏数据 |
| 吸附 | 靠近其它元素边缘或纸边 **8 点内**吸附并画辅助线；按住 `Shift` 整体按 8 点（=1 mm）步进 | 车间说的是"往右挪一毫米"，8 点在 203dpi 下正好 1 mm |
| 缩放手柄 | 改的是 `mulX`/`mulY` **整数档位**（1→2→3…），不是连续缩放；二维码改 `cell` 2–8；条码/线/框改 `h`/`w` | 打印机只认整数倍率；连续缩放会配出一堆打不出来的值 |
| 重叠命中 | 倒序命中（后画的在上层优先）+ `Tab` 循环选中 + 左侧层级列表可点选 | 80×60 上盒子叠盒子很常见，只靠点击会选不中 |
| 键盘 | 方向键 ±1 点、`Shift+方向键` ±8 点、`Del` 删、`Ctrl+Z`/`Ctrl+Shift+Z`、`Ctrl+S` 保存 | 精修靠键盘比鼠标准 |
| 撤销栈 | 内存里 `rows` 快照，50 步，**不落库**、刷新即清 | 拖错一下就能回，代价最小；落库版本归 §7 快照管 |

### 5.4 屏上文字怎么做到"宽准"

每个拆行后的盒子（§3.2 的 `segments`）就是它的真实占位：盒子高定 CSS 字号，盒子宽定实际宽度，**偏差超过 2% 时用 `scaleX` 把字拉到盒子宽**。
结果是"**位置准、宽准、字形仍不是打印机的 24×24 点阵**"。所以"最终以实纸为准"这句话必须留在画布上方，沿用 [docs/32 §6.3](32_标签层设计规格.md) 那条已经立好的规矩（同一句警告也已经在 `LabelPreviewService` 的类注释里）。

### 5.5 错误处理

本项目最难发现的一类问题是"静默空白"，所以显式定死三条：

- **`resolve` 失败（网络/500）**→ **保留上一次盒子，不清空画布**，顶上一条黄字「几何刷新失败，显示可能过时」，保存按钮仍可用——服务端闸仍是最终裁判。
- **403** → 明说「无权限访问: base:label:template」，**不静默降级成只读画布**。
- **过期响应** → 照抄 `LabelCenter.vue` 已有的 `previewGen` 号数丢弃规矩，**不发明第二套竞态处理**。

## 6. App 现场微调

### 6.1 新页与入口

`app/src/pages/base/label-tune.vue`，入口是现有打印页画布下方一个「微调版式」按钮（画布本身在 `label-print.vue:52-58`）。

手机能改的只有三样：**位置（拖）、宽/高倍率（± 步进；二维码是 `cell` 步进）、份数**。
不给：新建/删除模板、纸头（尺寸/dpi/间隙）、字段映射、旋转（P3）。

### 6.2 四条必须遵守的既有教训（写进设计，不等实施时再撞）

1. **深链参数走 `utils/routeQuery.js` 模块级上下文**：`setLabelTuneContext(templateId, bizType, bizId, lineIds)`，**不用 props 传**。
   v1.1.140/141 两次实测：同路由换 query 连页面自己都不重建；子组件的 camelCase props 会被 keep-alive 保住上一趟的旧值（kebab 键新、camel 键旧），`:key`/`v-if`/`$nextTick` 都拦不住。
2. **步进与 PC 相反**：手机屏宽 360 px，扣掉页边距后可用约 344 px，80 mm ≈ 4.3 px/mm，1 点（0.125 mm）只有半个像素，跟手拖不动。所以 App 默认按 **8 点（=1 mm）** 步进、长按切 1 点精修；PC 默认 1 点。这不是风格差异，是物理分辨率决定的。
3. **App 的画布用"正要打的这张真实单"的数据**，不用 §3.4 的示例值——现场场景本来就是"拿着这张单发现歪了"。`sample` 只服务 PC 设计期没有单可挑的时候。
4. **权限判定双条件**，照抄 [label-print.vue:179](../app/src/pages/base/label-print.vue#L179) 那句
   `getAppPermissions().includes(perm) && isPermEnabled(...)`（R10），并且**必须留 `isAdmin()` 兜底**——v1.1.156 就是超管在库里只有 PC 授权行，App 端 perm-only 入口直接看不见。

## 7. 快照与回滚

### 7.1 表 `base_label_template_hist`（sql/158）

镜像主表里**能回滚的那几列**，其余（`template_code`/`template_name`/`is_default`/`status`/`remark`）不进历史：回滚要恢复的是"这张纸长什么样"，不是"这张纸叫什么名字"。

| 列 | 说明 |
|---|---|
| `id` | 雪花 id |
| `template_id` | → `base_label_template.id`（**不加外键**，软删主行时不该级联删历史） |
| `seq` | 同模板内递增版本号，`KEY (template_id, seq)` |
| `biz_type` / `width_mm` / `height_mm` / `gap_mm` / `dpi` / `direction` / `copies` | 纸头快照，与主表同口径 |
| `elements` | LONGTEXT，与主表同口径 |
| `create_by` / `create_time` | 谁在什么时候存的这一版（回滚要知道该找谁） |

### 7.2 写入位置：只有一个

`BaseLabelTemplateService.update()`（[:76](../backend/src/main/java/com/industrial/erp/modules/base/service/BaseLabelTemplateService.java#L76)）在覆盖主表**之前**，把当前行插进 hist，**同一个事务**。

- 不按入口分叉：PC 画布、PC 老表格 tab、App 微调、以后的 Excel 导入，全都自动留痕。"哪个入口会留版本"不该是需要背的知识。
- `add()` 不写快照（没有"上一版"）。
- `delete()` 不写快照——删除本来就走软删，恢复把 `deleted` 改回 0 就行，两套恢复机制叠起来只会让现场不知道该点哪个。
- **保留最近 20 版**，超出裁最旧。微调是按点挪来挪去的，不裁会随试错次数线性涨；而没人需要回退到第 30 版。

### 7.3 端点

```
GET  /base/label/template/{id}/history        → 列表：seq / create_time / create_by 姓名 / elements 字节数 / 元素数
GET  /base/label/template/{id}/history/{seq}  → 单版全量（含 elements）
POST /base/label/template/{id}/rollback  { seq }
```

权限全部复用 `base:label:template`，**不新建权限点**——所以 §6.3 那一行 APP 授权同时管住保存和回滚。列表端点故意不回全量 JSON：20 版 × 2 KB 是白扔的带宽，点开某版再拉。

### 7.4 rollback 的语义（钉死）

**先把当前行存成新的一版快照，再把历史那版写回主表。**
即回滚本身可以再回滚：连点两次「回上一步」能回到原地。反过来的设计（回滚不留痕）一旦多点一次就真把内容丢了。

回滚要照常过 §3.2 的保存闸吗？**要**。历史版本是当时通过闸存进来的，但如果中间 `LabelGeometry` 的度量改过（B3b 那种改动），历史版就可能按新度量不合法——这时拦住并报闸的错误，比静默存进去再打出半张纸好。

### 7.5 UI 不对称是有意的

- **PC**：右上角「版本历史」抽屉，列 seq/时间/操作人/元素数，任选一版「回滚到这版」。
- **App**：微调页顶部只有一个「↩ 回上一步」，**不做列表**。手机上没地方铺 20 行，而且现场要的是"刚才那下挪坏了"，不是考古。

## 11. 验收清单（端到端，必须实纸）

1. PC 打开「标签模板」→ 画布 tab，80×60 画布按 1 mm=6 px 显示，示例值填满各字段、无橙无红。
2. 拖一个文本元素 8 点 → 松手 → `resolve` 回的新盒子坐标 = 原坐标 + 8；纸宽方向超长的内容自动**拆成两段盒子**，第二段 y 下移一个行高。
3. 属性面板把宽倍从 1 调到 2 → 盒宽翻倍、字高不变；保存 → 导出 TSPL，`TEXT` 里 `mulX=2, mulY=1` 逐字符可见。
4. 造一个 `field` 指向该 bizType **不存在**的字段的元素 → 画布上该盒子标橙、不点保存就知道；点保存**被服务端拦**，且报的序号与文案和画布上那条一致（§3.2 要点 1）。
   4b. 必填字段取值为空 → 画布上该盒子**标红**，但**保存与打印照常放行**（沿用 [docs/32 §5](32_标签层设计规格.md) 那条既有裁定：车间不能因为一个代号空就停下不出标签）。这一条**故意与上一条不对称**，别在画布上顺手把"空值"也做成拦保存的错误——那会改变既有打印行为。
5. 保存 → 「版本历史」里出现旧版 → 回滚 → 再导出 TSPL，指令串回到上一版。
6. 打印这张（P1：走 PC 导出的 TSPL 文本 / P2：手机蓝牙）→ **实纸与画布逐项对照**：位置、行数、字高、二维码可扫、条码可扫。这一条是本设计 D1 的唯一验法。
7. App：车间手机 → 标签打印中心 → 选一张真实单 → 「微调版式」→ 拖正 → 直接打印 → 纸面正。
8. App：非超管（生产主管）能进微调页并保存；只授 `base:label:list` 的账号入口不可见且接口 403（T7）。
9. 存量三条种子模板：本次改动前后**渲染出的指令串逐字节相同**（T1/T4 的机器版即这条）。
